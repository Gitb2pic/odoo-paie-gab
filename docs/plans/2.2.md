## 3. Extensions de modèles avancées à l'étape 2.2 (décision P2)

Les rubriques générées doivent porter leur traitement social/fiscal dès leur création (RG22 + « toute rubrique a un traitement social et fiscal ») : les **champs** de `hr.salary.rule` (prévus en 2.3) sont créés maintenant ; leur **vue** (bloc « Fiscalité Gabon ») reste à l'étape 2.3.

| Champ (`hr.salary.rule`) | Type | Valeurs |
|---|---|---|
| `l10n_ga_social_base` | Selection | `subject` / `excluded` / `capped` / `none` (retenues, totaux, charges) |
| `l10n_ga_tax_base` | Selection | `taxable` / `exempt` / `capped` / `none` |
| `l10n_ga_social_cap_group` | Char | code de `SOCIAL_CAPS` (obligatoire si `capped`, contrôlé par `@api.constrains` contre le registre du noyau) |
| `l10n_ga_tax_cap_group` | Char | code de `TAX_CAPS` (idem) |
| `l10n_ga_prorate` | Boolean | proratisée par la présence (utilisé en 2.3) |
| `l10n_ga_leave_base` | Boolean | base de l'allocation de congé |
| `l10n_ga_severance_base` | Boolean | base des indemnités de rupture |
| `l10n_ga_das_column` | Selection | `presence`, `benefit`, `food`, `taxable_allowance`, `leave`, `nt_housing`, `nt_transport`, `nt_domestic`, `nt_other`, `none` (base `06` §3.1) |

Noms : ceux du prompt 2.3 (`_social_base` / `_tax_base` + `_cap_group`), plus précis qu'ADR-17 §4 (`l10n_ga_social_group` / `l10n_ga_tax_group`) et compatibles avec lui (`excluded` ↔ `EXCLUDED`, `exempt` ↔ `EXEMPT`, `capped` ↔ groupe plafonné). Le compte cible reste dans le CSV seulement : les comptes sont `company_dependent` (sprint 0 point 4) et seront affectés par `_configure_payroll_account_ga` à l'étape 3.

`hr.work.entry.type.l10n_ga_pay_mode` : Selection `paid` / `unpaid` / `cnss` (pris en charge CNSS : maternité, AT en subrogation) ; les types `unpaid` sont aussi dans `unpaid_structure_ids` = structure Gabon (mécanisme standard de non-paiement).

## 4. Données

- **Type de structure** « Gabon : Employé » ; **structure** « Gabon — Employé » (`GA_EMP`, `rule_ids = []`, `default_struct_id` du type).
- **Catégories** : standard réutilisées `BASIC`, `ALW`, `GROSS`, `DED`, `NET`, `COMP` ; Gabon : `GA_AIK` (avantages en nature : dans le brut, **hors net**), `GA_SOC` (retenues sociales, parent `DED`), `GA_TAX` (retenues fiscales, parent `DED`), `GA_EMPLOYER` (charges patronales, parent `COMP`), `GA_CASH` (arrondi espèces F2, étape 2.6).
- **Règles standard conformes** (générées depuis des lignes `standard` du CSV) : `BASIC` (`payslip.paid_amount`, seq 1), `GROSS` (`BASIC + ALW + GA_AIK`, seq 100), `NET` (`BASIC + ALW + DED`, seq 200 — **une seule**, jamais redéfinie ; `GA_AIK` hors net puisque non versé). Les règles fiscales (`GA_CNSS_SAL`, `GA_IRPP`…) et d'arrondi appellent l'adaptateur et arrivent aux étapes 2.3 et 2.6.
- **Rubriques de gain** (~60) : `amount_python_compute` générique `result = inputs['<code>'].amount` avec condition `'<code>' in inputs` (aucun nombre littéral) ; l'ancienneté, les HS, `GA_CONGE` calculés arrivent en 2.4 (ligne CSV présente, formule marquée `input` en attendant — la rubrique lit une entrée saisie).
- **Types d'entrée** : un par rubrique lue par entrée (`struct_ids` = structure Gabon, `country_id` Gabon) ; `available_in_attachments = True` pour les indemnités contractuelles (ADR-16, colonne CSV `input_kind = attachment`), `False` pour les variables du mois et **`GA_LOAN` (jamais `available_in_attachments`, sprint 0 point 6)** ; + `GA_ADVANCE` (avance/acompte), `GA_RECALL` (rappel), `GA_IRPP_REGUL` (régularisation).
- **Prestations** : `GA_HS_J`, `GA_HS_N`, `GA_HS_DIM`, `GA_HS_FER` (pas de taux : `amount_rate` laissé au défaut technique, `is_extra_hours = False`, calcul par la convention à l'étape 2.4, point 09-11) ; 12 absences F4 : congé payé (`paid`), maladie avec certificat (`paid`), maladie non payée (`unpaid`), maternité `GA_MAT` (`cnss`), accident du travail `GA_AT` (`cnss`), naissance, mariage, décès (`paid`, circonstances), absence justifiée non payée, absence injustifiée, mise à pied disciplinaire, sanction (`unpaid`).
- **Types d'absence** (`hr.leave.type`, `country_id` Gabon) : les 12, reliés à leur prestation ; `requires_allocation` pour le congé payé seul ; `unpaid` cohérent avec `l10n_ga_pay_mode`.
- **Séquence** `l10n_ga.employee.loan` (préfixe `PRET/%(year)s/`).

## 5. Catalogue `data/catalogue_rubriques_ga.csv` (F6)

Colonnes : `code`, `name`, `kind` (`standard` / `input`), `category`, `sequence`, `input_kind` (`attachment` / `monthly` / vide), `social_base`, `social_cap_group`, `tax_base`, `tax_cap_group`, `prorate`, `leave_base`, `severance_base`, `das_column`, `account` (cible `pcg_*` pour l'étape 3), `source`.
Construit ligne à ligne depuis la matrice base `05` §1 (≈ 40 lignes) en éclatant les familles pour atteindre ≈ 60 rubriques : 13e mois / prime de fin d'année / bilan / intéressement (`BONUS_4M`) ; risque / pénibilité / technicité / sujétion / diplôme / vie chère ; salissure / vestimentaire / blanchissage ; primes familiales (trousseau, scolarité, transport d'enfants, `FAMILY_20K`) ; transport (`TRANSPORT_35K` + `TRANSPORT_DAILY`), véhicule (`TRANSPORT_35K` + `VEHICLE_100K`), carburant / kilométrique (social `TRANSPORT_35K`, fiscal imposable — point 🔴 de la matrice) ; ISR retraite / décès (`ISR_RETIREMENT` social et fiscal), démission (soumise), plan social (exclue/exonérée) ; logement en espèces **imposable sans groupe** (D-14) ; avantages en nature `AN_*` (catégorie `GA_AIK`, valorisés par le noyau en 2.3) ; jetons de présence (hors structure salariale : exclus du catalogue, ID23 à l'étape 5 — noté dans le CSV comme commentaire de rapport). Chaque ligne cite sa source (article CGI / CT / arrêté, ligne de la matrice). Les points 🔴 non tranchés (panier, solidarité, carburant) prennent le traitement **le plus prudent** (imposable) et citent `09` / la matrice dans `source` (règle d'or 13 : le traitement reste modifiable sur la règle).

Codes : `GA_<CODE_MATRICE>` (ex. `GA_SURSAL`, `GA_TRANSP`, `GA_13M`) ; xml_id `rule_ga_<code minuscule>` stables.
