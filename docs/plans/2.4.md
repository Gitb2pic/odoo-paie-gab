## 2. Modèles (règle d'or 11 : `company_id` obligatoire, `check_company=True`, règles d'enregistrement)

| Modèle | Champs |
|---|---|
| `l10n_ga.collective.agreement` | `name`, `code`, `company_id`, `active`, `is_example` ; ancienneté : `seniority_start_years`, `seniority_start_rate`, `seniority_step_rate`, `seniority_max_rate` (0 = pas de plafond), `seniority_base` (`grade_minimum` / `wage`) ; `grade_ids`, `overtime_rate_ids` |
| `l10n_ga.overtime.rate` | `agreement_id`, `company_id` (related stocké), `period` (`day` / `night` / `sunday` / `holiday`), `hours_from`, `hours_to` (0 = sans limite), `rate` (majoration) ; contrainte tranches sans chevauchement |
| `l10n_ga.agreement.grade` | `agreement_id`, `company_id` (related stocké), `category`, `echelon`, `date_from`, `minimum_wage`, `hourly_rate` ; unicité (convention, catégorie, échelon, date) via `models.Constraint` |

`hr.version` : `l10n_ga_agreement_id`, `l10n_ga_grade_id` (domaine : grade de la convention), `l10n_ga_seniority_date` (défaut : première date de contrat ; modifiable pour la reprise et les suspensions).
Minimum applicable = grade de même (convention, catégorie, échelon) dont `date_from` est la plus récente ≤ date. **RG18 bloquant deux fois** : contrainte sur la version (à `date_version`) et anomalie `danger` du bulletin (à `date_to`, si la grille a été revalorisée depuis) → validation refusée par le mécanisme natif.

## 3. Calculs (noyau pur `labour.py`, aucun taux en dur)

| Rubrique | Calcul | Paramètres |
|---|---|---|
| `GA_ANC` | années révolues depuis `l10n_ga_seniority_date` à `date_to` ; taux = 0 avant `start_years`, puis `start_rate + step × (années − start_years)`, plafonné ; × base (minimum du grade à `date_to`, ou salaire) ; proratisée par la présence (catalogue) | convention |
| `GA_HS_J`, `_N`, `_DIM`, `_FER` | heures des prestations de la période × taux horaire × (1 + majoration de chaque tranche) ; taux horaire = salaire / `l10n_ga_hours_month_ref` (173,33) ou salaire horaire si la version est horaire | table de la convention ; **aucune valeur par défaut** (09-11) : heures sans taux → anomalie bloquante |
| `GA_CONGE` | jours de congé payé (`GA_CP`) : `max(A, B)` — A = maintien (salaire + indemnités « base congés » proratisées, au prorata des heures de congé) ; B = rémunération « base congés » des 12 mois précédents (bulletins validés) × ratio (1/12, 5/48 si moins de 18 ans) × jours ouvrables pris / jours ouvrables annuels | 5 paramètres datés (P1) |
| `BASIC` | inchangé : `paid_amount` (prestations) ; jamais de retenue ajoutée (B2) | — |

Les trois valeurs passent par `payslip._l10n_ga_compute('seniority' | 'overtime:day' | 'leave_allowance', ...)` : formules toujours en une ligne, générées depuis le catalogue.

## 4. Absences (F4)

| Type | Effet sur `BASIC` | Autre effet |
|---|---|---|
| congé payé `GA_CP` | **retiré** (ajouté à `unpaid_structure_ids`, nouveau mode `allowance`) | payé par `GA_CONGE` |
| maladie, naissance, mariage, décès | maintenu | — |
| maladie non payée, absences justifiée / injustifiée, mise à pied, sanction | retiré | — |
| maternité `GA_MAT`, accident du travail `GA_AT` | **maintenu si subrogation** (option société `l10n_ga_cnss_subrogation`, vrai par défaut), retiré sinon | créance CNSS : écriture à l'étape 3 |
