## 3. Modèles et champs

- **`l10n_ga.declaration.type`** (configuration partagée, sans société — comme `hr.payroll.structure`) : `code` (unique), `name`, `authority` (dgi/cnss/cnamgs), `periodicity` (monthly/quarterly/yearly), `period_basis` (payment_date/period), `due_months` + `due_day` (échéance = fin de période + N mois, jour J borné au dernier jour du mois : ID10 1/15, DTS 1/30, DAS 4/30), `lead_days` (J-10), `auto_create` (Observer/cron), `generator_key`, `template_path` (gabarit `.xlsx/.xlsm` du module), `report_id`, `active_from`/`active_to`, `box_ids`.
- **`l10n_ga.declaration.box`** : `type_id`, `code` (unique par type), `name`, `sequence`, `cell_ref` (`Feuille!P40` ou `P40`), `value_kind` (amount/number/rate/text/date), `is_total`, `auto_value` (en-tête : raison sociale, NIF, n° CNSS/CNAMGS, mois, année, dates), `source_codes` (codes de rubriques pour le générateur générique : les codes viennent des données, jamais du code Python).
- **`l10n_ga.declaration`** (`mail.thread`, `mail.activity.mixin`) : `name` (stocké), `company_id`, `currency_id`, `type_id`, `date_from`, `date_to`, `due_date` (calculé stocké, modifiable), `state`, `amount_total` (Σ cases « total », stocké), `line_ids`, `detail_ids`, `issue_ids`, compteurs d'anomalies, `rectified_id` / `rectification_ids`, `filing_date`, `filing_number`, `validated_date`, `validated_by_id`, `sha256`, `snapshot_attachment_ids`, `declarant_id`.
  - Contraintes : `date_to >= date_from` (`models.Constraint`) ; `UniqueIndex (company_id, type_id, date_from, date_to) WHERE rectified_id IS NULL AND state != 'cancel'` (RG11).
  - Méthodes : `action_compute` (Template Method), `action_validate`, `action_unvalidate`, `action_mark_filed`, `action_mark_paid`, `action_reset_draft`, `action_cancel`, `action_create_rectification`, `action_check_integrity`, `_ensure_state`, `_TRANSITIONS`, `_snapshot_payload`, `_compute_sha256_value`, `_render_xlsx`, `_render_pdf`, `_l10n_ga_on_payslips_done`, `_cron_prepare_due_declarations`, `_period_bounds(type, day)`.
- **`.line`** : `declaration_id`, `box_id`, `value_amount` (Monetary), `value_number` (Float), `value_text`, `value_date` ; `UniqueIndex/Constraint unique (declaration_id, box_id)`.
- **`.detail`** : `declaration_id`, `box_id`, `employee_id`, `partner_id`, `label` (figé), `amount`, `payload` (`fields.Json`), `payslip_line_ids` (M2M). `move_line_ids` : ajouté par `l10n_ga_dgi_edi_account` (étape 5, dépendance comptable — règle d'or 14).
- **`l10n_ga.check.issue`** (extension) : `declaration_id` (cascade), `scope` + `('declaration', 'Déclaration')` (`ondelete='cascade'`).
- **`res.company`** : `l10n_ga_declarant_id` (utilisateur destinataire des activités ; à défaut les membres du groupe Déclarant de la société).

## 4. Moteur

1. **Registre** `l10n_ga.declaration.generator._get(key)` → `env['l10n_ga.declaration.generator.<key>']`, `KeyError` sinon ; `_has(key)`.
2. **Interface** `...generator.base` : `_collect`, `_fill`, `_details`, `_checks`, `_required_parameters` (codes de paramètres à contrôler).
3. **Générateur générique `payslip`** : `_read_group` des `hr.payslip.line` des bulletins **validés/payés** de la société, filtrés sur `l10n_ga_payment_date` (base « date de paiement ») ou `date_to` (base « période ») ; chaque case = Σ des `source_codes` ; détail par salarié et par case avec `payslip_line_ids`. Base réutilisable par ID10/ID28/DTS (4.2-4.3).
4. **`action_compute`** : garde d'état → collecte → `_write_boxes` (arrondi au franc **par case**, règle d'or 9 ; taux et textes non arrondis) → cases d'en-tête `auto_value` → `_write_details` → contrôles (générateur + `COMMON_CHECKS`) → `computed`.
5. **Contrôles `COMMON_CHECKS`** : `GA_DECL_NO_CNSS` (salarié du détail sans n° CNSS, bloquant), `GA_DECL_DUPLICATE` (autre déclaration active chevauchant la période, bloquant), `GA_DECL_PARAM_MISSING` (paramètre requis sans valeur à `date_to`, bloquant), `GA_DECL_TOTALS` (case ≠ Σ détails de la case, écart > 0, bloquant). Les classes de contrôle paie (`CheckRule`) sont réutilisées comme base.
6. **Validation** (déclarant seulement) : refus si anomalie bloquante (RG15) → instantané : lignes et détails déjà stockés, empreinte SHA-256 d'un JSON canonique (cases + détails triés), fichiers Excel et PDF joints, date et auteur ; lignes et détails deviennent non modifiables (verrou `write/unlink`).
7. **Rectificative** : depuis « déposée » ou « payée », copie brouillon liée (`rectified_id`) ; l'originale reste intacte.
8. **Observer** : `hr.payslip.action_payslip_done` et `action_payslip_paid` → `_l10n_ga_on_payslips_done(slips)` : pour chaque société × type actif `auto_create` dont le générateur existe, période contenant la date de paiement (ou `date_to`) : crée la déclaration brouillon ou recalcule une déclaration brouillon/calculée ; une déclaration déjà validée n'est **jamais** recalculée — un message la signale (rectificative à envisager).
9. **Cron** quotidien `_cron_prepare_due_declarations()` : pour chaque société gabonaise × type actif `auto_create`, périodes dont l'échéance tombe dans `[aujourd'hui, aujourd'hui + lead_days]` : crée/calcule la déclaration, activité « Déclaration à déposer » (date limite = échéance) pour le déclarant, activité « Déclaration à corriger » s'il reste une anomalie bloquante ; pas de doublon d'activité.

## 5. Rendus

- Interface Builder (`renderers/base.py`) : `header(values)`, `boxes(cells)`, `table(sheet, start_row, rows)`, `build() -> bytes`.
- `XlsmTemplateRenderer(template_bytes)` : `openpyxl` `keep_vba=True`, écrit des **valeurs** (une chaîne commençant par `=` est forcée en texte), feuille par défaut = première feuille.
- `XlsxDeclarationBuilder` : réutilise `XlsxRenderer` de la paie (feuilles « Cases » et « Détails »), jamais de formule.
- Choix : gabarit défini sur le type → gabarit rempli ; sinon classeur neuf. PDF : rapport du type, sinon rapport générique.

## 6. Sécurité et vues

- Privilège « Déclarations Gabon » ; groupes `group_l10n_ga_declarant` (implique `hr_payroll.group_hr_payroll_user`) et `group_l10n_ga_declaration_manager` (implique le déclarant ; admin et root membres).
- Droits : gestionnaire de paie = lecture + création/calcul des brouillons ; déclarant = + validation, dépôt, paiement, annulation de validation ; responsable = + types/cases, suppression (brouillon/annulée seulement).
- Règles multi-société `company_id in company_ids` sur déclaration, ligne, détail.
- Menus : Paie › Déclarations Gabon (Échéances, Déclarations, Anomalies) ; Configuration › Types de déclaration.

## 10. Risques

- Tests PDF : en mode test, Odoo rend le HTML au lieu du PDF ; la pièce jointe est quand même produite (contenu vérifié non vide).
- Crons du service sur les bases de test : les tests appellent `_cron_prepare_due_declarations()` directement avec une date injectée.
- Volume : `_read_group` agrégé en SQL ; détails par salarié × case (≤ quelques milliers de lignes par mois).
