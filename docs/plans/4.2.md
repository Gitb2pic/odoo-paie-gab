## 3. Générateurs

- **Générateur générique `payslip`** (4.1) enrichi, toujours piloté par les données des cases :
  - `source_codes` signés (`-GA_IRPP` = retenue déclarée en positif) et `source_categories` (`ALW`, `GA_AIK`) — le booléen `negate` de 4.1 disparaît (D-77) ;
  - `source_measure` : `total` (montant), `base` (base figée `l10n_ga_base`), `cfp` (part retenue dans l'assiette CFP selon l'option société : total − part exclue sociale, ou total si « brut ») ;
  - `sum_box_codes` : case = somme d'autres cases (P43, total) ; `parameter_code` : case = paramètre daté à `date_to` (taux CFP), contrôlé par `GA_DECL_PARAM_MISSING` ;
  - `section` : groupe de cases (cadre CFP) que l'imprimé peut laisser vide.
- **`id10`** (hérite de `payslip`) : cadre 3 laissé **vide** si la société déclare la CFP sur l'ID28 ; contrôle d'arrondi CFP (|L6 × L7 − Σ CFP| > nombre de salariés → avertissement).
- **`id28`** (hérite de `payslip`) : `_applies(company)` faux si la CFP est sur l'ID10 (ni Observer ni cron) ; calcul manuel → anomalie bloquante `GA_ID28_CFP_ON_ID10` (jamais deux fois la CFP).
- Lecture : `_read_group` sur les lignes des bulletins **validés / payés**, filtrés sur `l10n_ga_payment_date` (base « date de paiement ») ; détails par salarié et par case.

## 4. Cases (données XML)

- **ID10** : en-tête (exercice, mois, NIF, raison sociale, BP, ville, téléphone, e-mail, site, code résidence) ; cadre 2 : `P40` IRPP (`-GA_IRPP, -GA_IRPP_REGUL`), `P41` TCS (`-GA_TCS`), `P42` FNH (`GA_FNH, -GA_FNH_SAL`), `P43` = P40 + P41 + P42 ; cadre 3 (section CFP) : `R49` salaire de base (`BASIC`, mesure `cfp`), `R50` avantages en numéraire (catégorie `ALW`, mesure `cfp`), `R51` CNSS (`-GA_CNSS_SAL`), `R52` CNAMGS (`-GA_CNAMGS_SAL`), `R53` avantages en nature (catégorie `GA_AIK`, mesure `cfp`), `R54` base CFP (`GA_CFP`, mesure `base`), `R55` taux (`l10n_ga_cfp_rate`), `R56` CFP due (`GA_CFP`). Total dû = P40 + P41 + P42 + R56.
- **ID28** : même en-tête (cellules ID28), `Q37` salaires de base, `Q38` numéraire, `Q39` CNSS, `Q40` avantages en nature, `Q41` base, `Q42` taux, `Q43` CFP due (total dû).
- Types : mensuels, base « date de paiement », échéance le 15 du mois suivant, préparation J-10, gabarit `static/templates/…`, rapport PDF dédié.

## 5. Quittances (F11, RG16)

- `l10n_ga.declaration.payment` : déclaration, société (liée), date, montant, n° de quittance, nature (`rs` / `fnh` / `cfp` / `other`), mode (espèces / chèque / virement), pièces jointes, note. `move_id` : étape 5 (D-73).
- Saisie par le déclarant sur une déclaration **validée, déposée ou payée** ; plusieurs quittances par déclaration.
- Déclaration : `amount_paid`, `amount_residual` stockés ; **« déposée » → « payée »** automatiquement quand Σ quittances ≥ total dû ; retour à « déposée » si une quittance est supprimée ou réduite ; « Marquer payée » refusé tant que le total n'est pas couvert ; sur-paiement → anomalie d'avertissement `GA_DECL_OVERPAID` + message dans le fil.
