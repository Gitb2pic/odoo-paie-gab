## 2. Import Excel des variables (F3, patron 13)

Assistant `l10n_ga.payslip.input.import` ouvert depuis un lot **brouillon** (`01_ready`) :

1. **Modèle** (`xlsxwriter`) : une ligne par bulletin brouillon du lot — `Matricule` (`registration_number`), `Salarié` (informatif), puis une colonne par **type d'entrée utilisable** sur la structure du lot (`struct_ids` vide ou contenant la structure ; `GA_LOAN` exclu : alimenté par les échéances) et une colonne d'heures par type `GA_HS_J`, `GA_HS_N`, `GA_HS_DIM`, `GA_HS_FER`. En-tête = **code** + libellé (`GA_TRANSP — Prime de transport`) ; ligne 1 figée.
2. **Lecture** (`openpyxl`, `read_only=True, data_only=True`) → liste de lignes brutes `{row, cells}` (côté wizard).
3. **Filtres purs** (`lib/ga_fiscal_core/input_import.py`), chacun `rows → (rows, issues)` :
   `normalise_headers` (code avant « — », colonne inconnue ou en double → anomalie, colonne ignorée ; `Matricule` absent → anomalie fatale) · `resolve_employee` (matricule du lot, sinon nom exact unique) · `resolve_columns` (type d'entrée / type d'heures) · `parse_amount` (nombre, texte « 1 500 » ou « 12,5 » accepté, négatif refusé, cellule vide = inchangé) · `check_in_batch` (salarié absent du lot → refus) · `dedupe` (salarié présent deux fois → **les deux lignes refusées**). Une anomalie ne rejette que sa ligne (ou sa cellule), jamais le fichier entier (sauf en-tête fatal).
4. **Aperçu** : nombre de lignes acceptées / refusées, liste des anomalies (ligne, colonne, message) ; bouton « Importer » actif s'il reste au moins une ligne valide.
5. **Écriture** : montants → `hr.payslip.input` du bulletin marqués `l10n_ga_imported` (la valeur importée **remplace** les saisies non automatiques du même type ; `0` supprime ; les entrées d'indemnité automatiques du même type s'effacent par la règle 2.5 « manuel prioritaire ») ; heures → `hr.work.entry` marquées `l10n_ga_imported` sur la version du bulletin, **heures décimales**, réparties sur les jours de la période en partant du dernier jour, sans dépasser 24 h par jour (contrainte standard) ; un réimport remplace les prestations importées du même type.
6. **Recalcul** : prestations relues (`_compute_worked_days_line_ids`) puis `compute_sheet()` des bulletins modifiés (soumis au blocage RG26 du §3).

## 3. Contrôles avant paie (F8, RG26, ADR-18)

`l10n_ga.check.issue` exactement comme ADR-18 §1 : `company_id`, `scope` (`payslip_run`), `payslip_run_id`, `payslip_id`, `employee_id`, `severity` (`blocking` / `warning`), `code`, `message`, `res_model`, `res_id` ; règle multi-société ; lecture paie, écriture réservée au code.

Chaîne `PAYROLL_CHECKS` (une classe par contrôle : `code`, `severity`, `run(slips) → [issue]`) :

| Code | Contrôle | Gravité proposée |
|---|---|---|
| `GA_NO_VERSION` | pas de version valide sur la période | bloquant |
| `GA_NO_HIRE_DATE` | date d'embauche (`contract_date_start`) absente | bloquant |
| `GA_NO_MARITAL` | situation familiale absente | bloquant |
| `GA_FORCED_PARTS_NO_REASON` | parts forcées sans motif | bloquant |

| `GA_ALLOWANCE_FORCED_NO_REASON` | indemnité forcée imposable sans motif | bloquant |
| `GA_NO_CNSS` / `GA_NO_NIF` | n° CNSS (`ssnid`) / NIF absent | avertissement (bloquant dans les déclarations, étape 4) |
| `GA_NO_BANK` | virement sans compte bancaire principal | avertissement |
| `GA_LOAN_OVER_RATIO` | échéances de la période > 40 % (paramètre daté) du net de référence | avertissement |

Déroulé :
- **« Contrôler »** sur le lot : supprime les anomalies du lot puis relance la chaîne (idempotent) ; exécutée aussi automatiquement dans `generate_payslips()` et avant `action_confirm()`.
- **Blocage RG26** : tant qu'un lot a une anomalie bloquante, `compute_sheet()` **ne calcule aucun** de ses bulletins Gabon (lignes vidées) ; `action_confirm()` (« Calculer ») lève une `UserError` listant les anomalies ; les bulletins restant vides, le bouton standard « Confirmer » reste masqué.
- **Pont natif** (ADR-18 §4) : `_get_errors_by_slip()` / `_get_warnings_by_slip()` renvoient les anomalies du bulletin → `action_payslip_done()` refusé par le standard, pas de second verrou.

## 4. Arrondi espèces (F2, RG23, patron 15)

| Règle (catégorie `GA_CASH`, séquences 201-203) | Montant |
|---|---|
| `GA_ROUND_PREV` | reliquat `l10n_ga_rounding_carry` du dernier bulletin **validé** du salarié dans la société (date de fin < date de début) |
| `GA_ROUND` | ajustement d'arrondi = `payé − (NET + GA_ROUND_PREV)` (≤ 0), via `cash_round(net, carry_in, step, final)` |
| `GA_NET_PAY` | `NET + GA_ROUND_PREV + GA_ROUND` = montant versé |

- Pas = `l10n_ga_cash_rounding` de la société si mode **espèces**, sinon 0 (le reliquat antérieur est versé en entier) ; `final` = bulletin de départ (solde de tout compte, reliquat versé intégralement).
- `NET` reste unique et inchangé (test RG22 étendu) ; `l10n_ga_rounding_carry` (= `−GA_ROUND`) **figé à la validation** (F7), jamais recalculé ensuite.
- Règles en une ligne `payslip._l10n_ga_compute('cash_prev' | 'cash_adjust' | 'cash_pay', …)` ; `_l10n_ga_check_lines` les rejoue.

- Verrou : modifiable / supprimable tant qu'aucun bulletin Gabon **validé** de l'année ne l'a utilisé ; ensuite, correction = annuler les bulletins (message explicite).

## 10. Risques

- Calcul bloqué pour tout le lot à cause d'un salarié : voulu par RG26 ; le salarié peut être retiré du lot (« hors cycle », standard) pour débloquer les autres.
- Les prestations importées sur un jour déjà validé seraient en conflit standard : l'import refuse la ligne (anomalie) au lieu de forcer.
- `generate_payslips()` standard : surcharge par contexte autour de `super()` (aucune copie du code standard).
