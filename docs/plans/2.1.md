## 2. Modèle de données du noyau

**`FiscalParams`** (frozen, tous les montants en FCFA, taux décimaux) :
`smig`, `cnss_ceiling`, `cnss_employee_rate`, `cnss_employer_pf_rate`, `cnss_employer_at_rate`, `cnss_employer_avid_rate`, `social_transport_cap` (35 000), `cnamgs_ceiling`, `cnamgs_employee_rate`, `cnamgs_employer_rate`, `tcs_rate`, `tcs_monthly_exemption`, `tcs_deduct_cnss`, `tcs_deduct_cnamgs`, `fp_rate`, `fp_annual_cap`, `max_children`, `irpp_brackets` (tuple de `(de, a, taux, constante)`), `irpp_min_withholding` (F14), `bonus_annual_cap` (4 000 000), `vehicle_monthly_cap` (100 000), `transport_daily_2_trips` / `_4_trips`, `family_monthly_per_child` (20 000), `isr_taxable_ratio_retirement` (0,5), `benefit_rates` (logement, domesticité, eau/élec., nourriture), `food_monthly_cap` (120 000), `fnh_rate`, `fnh_ceiling`, `fnh_employee_share` (0), `cfp_rate`, `cfp_ceiling`, `cfp_base` (voir D-10), `cash_rounding` (option société, 500 par défaut), `cash_denominations`.
`load_from_yaml(path, date, cash_rounding=500)` : valeur applicable = dernière `date_from ≤ date` (RG06) ; PyYAML importé dans la fonction seulement (outil de test, jamais utilisé par Odoo, qui passera par `hr.rule.parameter` à l'étape 2.2).

**`GainLine`** (frozen) : `code`, `amount`, `social_group`, `tax_group`, `forced_taxable=False`.
Groupes sociaux (`SOCIAL_CAPS`) : `None` (soumis), `EXCLUDED` (arrêté 016 art. 3), `TRANSPORT_35K` (transport + véhicule + carburant + km, cumul ≤ 35 000), `ISR_RETIREMENT` (50 %).
Groupes fiscaux (`TAX_CAPS`) : `None` (imposable), `EXEMPT` (art. 91 bis, frais), `VEHICLE_100K`, `TRANSPORT_DAILY` (jours de présence × 2 500 ou 5 000), `FAMILY_20K` (× enfants), `BONUS_4M` (cumul annuel, avec le déjà-exonéré de l'année), `ISR_RETIREMENT` (50 %).
Groupe inconnu → `ValueError` explicite. **Logement en espèces : aucun groupe** (entièrement imposable) tant que le point 09-5 est ouvert — documenté dans la docstring et dans le rapport.
Répartition : part exonérée d'un groupe répartie au prorata des lignes, arrondie au franc, écart d'arrondi porté sur la dernière ligne (le total du groupe est conservé).

**`PayslipFacts`** (frozen) : `lines` (tuple de `GainLine`), `benefits` (avantages à valoriser), `marital`, `children`, `disabled_children`, `extra_half_part`, `forced_parts`, `presence_ratio`, `presence_days`, `transport_trips` (2/4), `has_company_car`, `ytd_bonus_exempted`, `ytd_irpp_base`, `ytd_irpp_withheld`, `regularize` (dernier bulletin de l'année ou départ).

**`PayResult`** (frozen) : champs de `04` §1 (`social_base`, `cnss_employee`, `cnamgs_employee`, `tcs_base`, `tcs`, `tax_parts`, `irpp`, `irpp_regularisation`, `cnss_employer_pf/at/avid`, `cnamgs_employer`, `fnh`, `fnh_employee`, `cfp`) + `gains`, `taxable_gross`, `irpp_base_monthly`, `annual_net_taxable`, `quotient`, `total_employee_deductions`, `net`, `employer_cost`, `lines` (par ligne : part exclue sociale, part exonérée fiscale), `bonus_exempted` (pour le cumul annuel).

Arrondi (règle d'or 9) : `round_fcfa` = demi vers le haut, par `Decimal` (même résultat que `float_round(x, 0)` d'Odoo), appliqué **à chaque montant de ligne** (cotisations, TCS, IRPP, charges, parts exonérées), jamais aux intermédiaires (RNI, quotient). L'oracle utilise `round()` (arrondi bancaire) : tolérance de 1 FCFA dans le test de parité, comme prévu par C5.

## 3. Algorithme (`04` §7 de la base)

1. Avantages en nature valorisés → lignes de gain (`benefits.py`).
2. Exonérations par ligne et par groupe (`exemptions.py`).
3. `social_base = max(SMIG × présence, Σ soumis)` ; CNSS/CNAMGS salariés et patronaux sur les plafonds.
4. `taxable_gross = gains − exonérations fiscales` ; `tcs_base = taxable_gross − CNSS sal. − CNAMGS sal. (option)` ; `TCS = taux × max(0, base − 150 000)`.
5. `irpp_base_monthly = tcs_base − TCS` ; ×12 ; abattement 20 % plafonné 10 M ; parts ; barème ; ÷12 ; seuil F14 (si `0 < IRPP ≤ seuil` → 0).
6. Régularisation (si `regularize`) : IRPP annuel dû sur le cumul réel (`ytd_irpp_base + irpp_base_monthly`, abattement sur le cumul) − déjà retenu − IRPP du mois.
7. FNH (part salariale paramétrable, 0 par défaut), CFP (base selon `cfp_base`), net, coût employeur.
